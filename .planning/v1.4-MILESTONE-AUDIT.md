## Critical Gap: PANE-03 — FilterDefining Dialog Broken in Multi-Pane Mode

**FAIL-1 (integration checker):** `handle_filter_defining_key` Enter arm and live-preview arm in `app.rs` write to `self.filter_query` (global state) instead of `self.active_pane_mut().filter_query`.

**Impact:** Pressing `F` to open the Filter Definition panel, typing a query, and pressing Enter produces no visible change to the active pane's task list in multi-pane mode. The global `self.filter_query` is updated but `rebuild_and_reanchor()` applies `pane.filter_query` (unchanged) to the pane's display rows.

The regular filter panel (`f` key / `Filtering` mode) is **correctly** wired to the per-pane state and is unaffected.

**Fix (minimal):**
In `app.rs handle_filter_defining_key`:
```rust
// Enter arm — change FROM:
self.filter_query = ...;
// TO:
self.active_pane_mut().filter_query = ...;

// Live-preview arm — change FROM:
self.filter_query = self.filter_defining_state.as_ref()...;
// TO:
self.active_pane_mut().filter_query = self.filter_defining_state.as_ref()...;
```
