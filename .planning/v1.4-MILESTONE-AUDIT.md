## Critical Gaps

### GAP-1 — Single-Pane Mode: Filter/Sort/Group Has No Effect (PANE-03, PANE-04) — Critical

**Root cause:** `rebuild_display_indices()` at app.rs:1563 reads `self.filter_query`, `self.sort_order`, `self.grouping` — global fields initialized to `""` / `FileOrder` / `false` in `App::new()` and **never mutated** by any Phase 25+ hotkey.

All Normal-mode hotkeys (`filter_toggle`, `clear_filter`, `1-9 presets`, `sort_cycle`, `group_toggle`) now write **exclusively** to `active_pane_mut()` fields (correct for multi-pane mode). But `rebuild_and_reanchor()` only calls `rebuild_visible_rows()` (per-pane) when `!should_show_single_pane() && panes.len() > 1`. In all other cases (default single-pane startup, `panes_hidden == true`), it calls only `rebuild_display_indices()` (global empty state).

**When triggered:**
- Default startup: 1 pane → `should_show_single_pane()` → true → render uses global empty state
- After `Ctrl+P` hides panes → `panes_hidden == true` → `render_panes()` routes to `render_task_list()` (global)

**Effect:** User presses `f`, types filter, presses Enter → task list unchanged. User presses `s` to cycle sort → sort order unchanged. This is a **regression from v1.3** in the most common use case (single-pane default startup).

**Minimal fix:**
```rust
// In rebuild_and_reanchor(), before calling rebuild_display_indices():
if self.should_show_single_pane() || self.panes_hidden {
    let pane = &self.panes[self.active_pane];
    self.filter_query = pane.filter_query.clone();
    self.sort_order = pane.sort_order;
    self.grouping = pane.grouping;
}
self.rebuild_display_indices();
```

### GAP-2 — FilterDefining Panel Opens with Empty Pre-Fill (PANE-03) — Minor

**Location:** `app.rs` ~line 834
**Current:** `active_editor.insert_str(&self.filter_query);` ← always `""`
**Fix:** `active_editor.insert_str(&self.active_pane().filter_query);`

**Effect:** When the user presses `F` to open the filter definition panel, the editor is always blank even when the active pane has a filter set. The Enter save (fixed in Phase 28) correctly writes back to `active_pane_mut()` — only the read is wrong.
