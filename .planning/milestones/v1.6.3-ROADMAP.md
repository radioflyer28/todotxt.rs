# Milestone v1.6.3: TUI UX tweaks, filter OR operator, recurring tasks, done.txt rotation

**Status:** ✅ SHIPPED 2026-05-19
**Phases:** 46-50
**Total Plans:** 12

## Overview

`v1.6.3` was a tight power-user milestone focused on finishing several high-value workflow
improvements without reopening the broader product surface. It added token-local OR filters,
inactive-pane readability polish, recurring task completion, monthly `done.txt` rotation, and
faster TUI date/token input ergonomics.

## Phases

### Phase 46: Filter Engine Upgrade

**Goal**: Add OR-capable filter terms without regressing existing AND semantics.
**Depends on**: None
**Plans**: 2 plans

Plans:

- [x] 46-01: Core parser/evaluator OR support
- [x] 46-02: CLI help contract and integration coverage

**Details:**
- Requirements: `FILT-01`, `FILT-02`, `FILT-03`
- Token-local OR shipped in the shared filter engine with explicit empty-branch tolerance.
- CLI help now documents supported OR syntax and explicitly calls out unsupported grouped
  negation.
- Integration coverage proves positional OR, `--filter` OR, AND composition, and malformed-edge
  tolerance.

### Phase 47: TUI Readability

**Goal**: Make grouped and multi-pane views easier to parse visually and easier to navigate.
**Depends on**: Phase 46
**Plans**: 2 plans

Plans:

- [x] 47-01: Active-only pane cursor highlight
- [x] 47-02: Group spacer rows and task-only navigation

**Details:**
- Requirements: `TUI-01`, `TUI-02`
- Inactive panes now preserve selection state without rendering a visible cursor highlight.
- Grouped rows gained blank spacer rows before non-first headers.
- Navigation normalizes to task rows only, skipping structural rows consistently in single- and
  multi-pane modes.

### Phase 48: Recurring Workflow Core

**Goal**: Add recurring task completion with implicit next-occurrence generation and reusable behavior across CLI and TUI.
**Depends on**: Phase 47
**Plans**: 3 plans

Plans:

- [x] 48-01: Core recurrence parser and next occurrence construction
- [x] 48-02: CLI recurring completion integration
- [x] 48-03: TUI recurring completion integration

**Details:**
- Requirements: `REC-01`, `REC-02`, `REC-03`, `REC-04`
- `todotxt-core` now parses `rec:` rules directly from todo.txt tokens and constructs the next
  occurrence deterministically.
- CLI `do` and TUI completion both auto-create the next recurring task without prompting.
- Bulk completion paths generate exactly one new task per newly completed recurring item.

### Phase 49: Archive Hygiene

**Goal**: Add time-based done.txt rotation with monthly cadence, future-ready cadence configuration, and explicit archive feedback.
**Depends on**: Phase 48
**Plans**: 3 plans

Plans:

- [x] 49-01: Shared cadence/config contract and rotation helper
- [x] 49-02: CLI archive rotation integration
- [x] 49-03: TUI archive rotation integration

**Details:**
- Requirements: `DONE-01`, `DONE-02`, `DONE-03`
- Archive rotation now happens during archive writes when a new monthly period begins.
- Prior archive contents move into deterministic files like `done-2026-05.txt`.
- CLI and TUI both surface rotation explicitly while preserving their existing archive safety
  semantics.

### Phase 50: Input Ergonomics

**Goal**: Make date entry faster and less repetitive while improving auto-select behavior in match-driven dialogs such as project and context token selection.
**Depends on**: Phase 49
**Plans**: 2 plans

Plans:

- [x] 50-01: TUI date-target cycling and week-jump navigation
- [x] 50-02: TUI quick-setter auto-select continuity behavior

**Details:**
- Requirements: `DATE-UX-01`, `DATE-UX-02`, `AUTO-SEL-01`, `AUTO-SEL-02`
- The TUI `s` date workflow now cycles due, threshold, and completed date targets in place.
- Date picker `Left`/`Right` navigation jumps by week.
- Project/context quick setters now prefer continuity by selecting the task's current token when
  possible instead of resetting to an arbitrary first match.

## Milestone Summary

**Key Decisions:**

- Keep OR support token-local and leave grouped negation out of scope for parser stability.
- Make recurring completion implicit rather than prompt-driven.
- Ship time-based archive rotation monthly first, but name configuration around future cadence
  expansion.
- Keep Phase 50 on the Rust TUI/core path after correcting an initial mistaken client-side start.

**Issues Resolved:**

- Closed the missing Phase 46 verification artifact.
- Converged milestone requirements and roadmap state so closeout documents match shipped behavior.
- Removed repeated friction in date setting and project/context quick-setter selection.

**Issues Deferred:**

- GUI interface (native desktop)
- CI/CD release pipeline and package distribution
- Retention cleanup and compression for rotated archive history

**Technical Debt Incurred:**

- No major new debt accepted for closeout; milestone finished with full phase validation coverage.
