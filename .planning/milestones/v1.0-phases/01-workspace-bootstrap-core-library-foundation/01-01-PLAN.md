From ToDoLib/Task.cs (C# regex patterns that define the todo.txt grammar):
```csharp
private const string CompletedPattern = @"^X\s((\d{4})-(\d{2})-(\d{2}))?";
private const string PriorityPattern = @"^(?<priority>\([A-Z]\)\s)";
private const string CreatedDatePattern = @"(?<date>(\d{4})-(\d{2})-(\d{2}))";
private const string DueDatePattern = @"due:(?<date>(\d{4})-(\d{2})-(\d{2}))";
private const string ThresholdDatePattern = @"t:(?<date>(\d{4})-(\d{2})-(\d{2}))";
private const string ProjectPattern = @"(?<proj>(?<=^|\s)\+[^\s]+)";
private const string ContextPattern = @"(^|\s)(?<context>\@[^\s]+)";
```

Parse order in C# constructor (sequential regex match-and-strip):
1. completed status (^X with optional date)
2. priority (^(A) )
3. due date (due:YYYY-MM-DD)
4. threshold date (t:YYYY-MM-DD)
5. creation date (YYYY-MM-DD after priority)
6. projects (+word)
7. contexts (@word)
8. remainder = body

Define `DueStatus` enum:

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[non_exhaustive]
pub enum DueStatus { NotDue, Today, Overdue }

Define `Task` struct (per CONTEXT.md Decision 3):
```rust
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "snake_case")]
#[non_exhaustive]
pub struct Task {
    #[serde(skip)]
    raw: String,
    pub completed: bool,
    pub priority: Option<char>,
    pub creation_date: Option<chrono::NaiveDate>,
    pub completion_date: Option<chrono::NaiveDate>,
    pub due_date: Option<chrono::NaiveDate>,
    pub threshold_date: Option<chrono::NaiveDate>,
    pub projects: Vec<String>,
    pub contexts: Vec<String>,
    pub body: String,
}
```

Implement `Task::parse(line: &str) -> Self` — infallible (per CONTEXT.md Decision 2):
- Use `winnow` combinators for positional prefix parsing (completed marker, priority, creation date)
- For body tags (projects `+word`, contexts `@word`, `due:YYYY-MM-DD`, `t:YYYY-MM-DD`): scan the remaining text to extract them
- Priority is UPPERCASE ONLY: `[A-Z]` — do not match lowercase (fixes C# bug M-6)
- Store original line as private `raw` field
- Sort and deduplicate projects and contexts (matching C# `SortedSet`)
- If parsing any field fails, treat the whole line as body text (raw task, no error)

Implement `to_raw(&self) -> &str` — returns the stored raw string.

Implement `Display for Task` — delegates to `to_raw()`.

Implement builder methods (per CONTEXT.md Decision 4 — take `self` by value, return new `Task`):
- `with_completed(self, completed: bool) -> Self`: If marking complete, strip priority from raw, prepend `x YYYY-MM-DD `. If unmarking, strip `x YYYY-MM-DD ` prefix.
- `with_priority(self, priority: Option<char>) -> Self`: Update priority in raw string. If currently has priority, replace `(X) ` with new `(Y) ` or remove it. If no priority, prepend `(X) `.
- `with_due_date(self, date: Option<NaiveDate>) -> Self`: Update or add/remove `due:YYYY-MM-DD` in raw string.
- `with_creation_date(self, date: Option<NaiveDate>) -> Self`: Update or add creation date.
- `with_threshold_date(self, date: Option<NaiveDate>) -> Self`: Update or add/remove `t:YYYY-MM-DD`.

Implement `due_status(&self) -> DueStatus`:
- If completed → `NotDue`
- If no due_date → `NotDue`
- If due_date < today → `Overdue`
- If due_date == today → `Today`
- Otherwise → `NotDue`

Implement relative date pre-processing:
- Before parsing, replace `due:today`, `due:tomorrow`, `due:monday` etc. with `due:YYYY-MM-DD`
- Same for `t:today`, `t:tomorrow`, etc.
- Use `std::sync::LazyLock<regex::Regex>` for the relative date patterns (not in the winnow hot path)
- Note: `regex` is NOT a dependency of todotxt-core yet — use string matching or add `regex` as a dependency if needed for relative date replacement only.
