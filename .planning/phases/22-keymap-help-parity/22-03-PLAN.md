**app.rs — add three new dispatch arms in handle_normal_key:**

Add these arms BEFORE the final `_ => {}` in handle_normal_key (after the '!' and '?' arms from Plans 02-03):

```rust
// '0' clear active filter (D-17, Phase 22 PAR-01)
_ if self.key_is_action(key, "clear_filter") => {
    self.filter_query.clear();
    self.toggled_filter_query = None;
    self.rebuild_and_reanchor();
}

// '1'-'9' apply preset f1-f9 (D-18, Phase 22 PAR-01)
// No-op if the slot is empty.
KeyCode::Char(c @ '1'..='9') if key.modifiers == KeyModifiers::NONE => {
    let slot_name = format!("f{}", c);
    if let Some(filter) = self
        .config
        .presets
        .get(&slot_name)
        .and_then(|p| p.filter.clone())
        .filter(|f| !f.trim().is_empty())
    {
        self.filter_query = filter;
        self.toggled_filter_query = None;
        self.rebuild_and_reanchor();
    }
}

// '.' manual reload from disk (D-19, Phase 22 PAR-01)
_ if self.key_is_action(key, "reload") => {
    match TaskList::load(&self.todo_path) {
        Ok(list) => {
            self.task_list = list;
            self.prune_stale_selections();
            self.rebuild_and_reanchor();
            self.pending_reload = false;
        }
        Err(e) => {
            // Log to stderr; TUI continues with stale data rather than crashing
            eprintln!("Warning: reload failed: {e}");
        }
    }
}
```

Note on '1'-'9': Use a direct `KeyCode::Char(c @ '1'..='9')` match arm rather than `key_is_action` because preset recall uses a range of 9 keys — there is no single "preset" action in the effective_keymap. These keys are intentionally NOT individually overridable (they are a compound range binding).

```markdown
# Deliberate Deviations from todotxt.net — v1.3 Milestone

This document records every intentional deviation between the Rust TUI
(`todotxt-tui`) and the reference Windows application (`todotxt.net`).
Captured as part of Phase 22 (PAR-03).

---

## DEV-01: Vim-style navigation (j/k) vs arrow-key primary

**todotxt.net:** Primary navigation is via arrow keys and mouse.
**todotxt-tui:** Primary navigation is `j`/`k` (vim-style). Arrow keys also work.
**Rationale:** TUI convention; no keyboard shortcut conflicts; arrow keys still functional.

---

## DEV-02: Lowercase action keys vs uppercase in todotxt.net

**todotxt.net:** Many hotkeys use uppercase letters (e.g., `J` for move down,
`N` for add, `U` for update, `D` for delete, `X` for mark done).
**todotxt-tui:** Lowercase: `n` add, `e`/`u` edit, `d` delete, `x` done, `o` sort.
`D` (uppercase/Shift+D) is reserved for bulk delete (Phase 20).
**Rationale:** Lowercase keys require no Shift press and reduce hand strain;
Shift+letter is reserved for extended/bulk variants.

---

## DEV-03: Disjoint selection mode (v + Space) — no equivalent in todotxt.net

**todotxt.net:** No multi-selection. Delete/append operate on cursor task only.
**todotxt-tui:** `v` toggles disjoint selection mode; `Space` marks tasks;
`Shift+j/k` extends contiguous range; `D`/`T` operate on the selection.
**Rationale:** Phase 19-20 feature addition. Exceeds todotxt.net's capabilities.

---

## DEV-04: 'I' (priority picker), 'P' (postpone), 'A' (archive) absent

**todotxt.net:** `I` opens priority picker, `P` postpones due date, `A` archives done tasks.
**todotxt-tui:** These keys are not implemented in v1.3.
**Rationale:** Each requires new UI flows (priority picker dialog, postpone dialog,
archive command). Deferred to Phase 23+ or v1.4.

---

## DEV-05: Filter toggle is Ctrl+F, not a single key

**todotxt.net:** Specific key to toggle filter visibility.
**todotxt-tui:** `Ctrl+F` toggles the active filter on/off.
**Rationale:** `f` is used to open the filter input panel; `Ctrl+F` avoids collision.

---

## DEV-06: No mouse support

**todotxt.net:** Mouse input supported for selection and scrolling.
**todotxt-tui:** Keyboard-only. Mouse events are not handled.
**Rationale:** TUI keyboard-first design. Mouse support is a potential v1.4+ enhancement.

---
```
