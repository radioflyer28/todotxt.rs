3. Add `save()` to `TuiConfig`'s `impl` block. Write to a temporary file first then rename for atomicity (prevents config corruption if the process is interrupted):

```rust
pub fn save(&self, path: &Path) -> color_eyre::Result<()> {
    let content = toml::to_string(self)
        .map_err(|e| color_eyre::eyre::eyre!("Failed to serialize config: {e}"))?;
    // Atomic write: write to .tmp then rename
    let tmp_path = path.with_extension("toml.tmp");
    std::fs::write(&tmp_path, &content)
        .map_err(|e| color_eyre::eyre::eyre!("Failed to write config tmp: {e}"))?;
    std::fs::rename(&tmp_path, path)
        .map_err(|e| color_eyre::eyre::eyre!("Failed to rename config tmp: {e}"))?;
    Ok(())
}
```

**Do not change** `load()`, `default_path()`, or `resolve_path()` — they are untouched.

**Note on field ordering in TOML output:** `toml::to_string` will emit all fields from `TuiConfig` including `todo_file`, `done_file`, `auto_creation_date`, `tui`, and `presets`. Fields with `None` values serialize as absent (correct for `Optional` fields with `#[serde(skip_serializing_if = "Option::is_none")]` — add this attribute to `todo_file` and `done_file` if they were previously absent from the file, to avoid inserting `todo_file = ...` where it wasn't present). Check if `todo_file` and `done_file` have `skip_serializing_if` already; if not, add:
