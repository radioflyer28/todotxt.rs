<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Plans 01 and 02 implemented:
    - New `theme.rs` module with `Theme` enum (Default/Light) and `StyleSheet` with priority/overdue styles
    - `TuiConfig` now deserializes `[tui] theme = "..."` from TOML config
    - `App` stores `styles: StyleSheet` and `no_color: bool` computed once at startup
    - `render_task_list()` applies `self.styles.priority_a/b/c` and `self.styles.overdue` per task row
    - NO_COLOR strips colors; DIM (completed) and REVERSED (selection) are preserved
  </what-built>
  <how-to-verify>
Run the TUI binary (built in Task 1: `cargo run --package todotxt-tui`) against a todo.txt file that contains:
- At least one priority (A) task: `(A) Something urgent`
- At least one priority (B) task: `(B) Medium priority thing`
- At least one priority (C) task: `(C) Low priority thing`
- At least one overdue task: `(A) Overdue thing due:2024-01-01`
- At least one completed task: `x done task`

**Check 1 — Default (dark) theme:**
Launch with no config `[tui]` block (or `[tui] theme = "default"`):
- Priority (A) tasks appear in bright red
- Priority (B) tasks appear in yellow
- Priority (C) tasks appear in cyan
- Overdue incomplete tasks appear in bold bright red
- Completed tasks appear dimmed, no color
- Selected row appears reversed (highlight), no additional color

**Check 2 — Light theme:**
Add `[tui]\ntheme = "light"` to config.toml and relaunch:
- Priority (A) tasks appear in standard red (visibly different from dark theme's bright red)
- Other elements similar to dark theme
- Selected and completed behavior unchanged

**Check 3 — NO_COLOR:**
Launch with `NO_COLOR=1 cargo run --package todotxt-tui`:
- No colored text anywhere in the task list
- Completed tasks still appear dimmed (DIM modifier preserved)
- Selected row still appears reversed (REVERSED modifier preserved)
- TUI is fully usable — all navigation and actions work

**Check 4 — Terminal restore (TUI-UX-04):**
a. Launch TUI, press `q` → terminal returns to normal, shell prompt visible
b. Launch TUI, press `Ctrl+C` → terminal returns to normal, shell prompt visible
c. To test panic restore: check that `color_eyre::install()` is called before `TerminalGuard::new()` in main.rs (already confirmed in Task 1)

**Check 5 — Auto-reload (TUI-UX-02):**
a. Launch TUI with your todo.txt
b. In a second terminal, append a line: `echo "(A) Hot-added task" >> /path/to/todo.txt`
c. Within ~500ms the TUI task list should update to show the new task without any keypress
d. Cursor should remain on the previously selected task (re-anchoring)
  </how-to-verify>
