## Objective

Implement quick context (`@`) and project (`+`) setters in Normal mode with autocomplete match lists and tab-to-complete selection.

**Purpose:** Enable fast metadata editing from Normal mode without entering full edit-mode; provide consistent token picker UX across capture flow.

**Output:** `@` and `+` quick setters (TAG-01/02/04/05) with idempotent token application, prefix + near-match ranking, and add-task/edit-task workflow preservation (CAP-01/02).

@.planning/PROJECT.md
@.planning/REQUIREMENTS.md
@.planning/phases/33-fast-capture-property-pickers/33-CONTEXT.md

Existing infrastructure reused from Phase 20 and earlier:
- `AutocompleteState` in state.rs for token popup and selection
- `collect_tokens(trigger)` in app.rs to generate candidate pool
- `handle_editor_key` pattern for Up/Down/Tab/Enter acceptance
- `render_autocomplete_popup` for popup display and navigation

Multi-select and bulk operation patterns from Phase 20:
- `selected_tasks: HashSet<usize>` for multi-task targeting
- `disjoint_select` flag for extended selection mode
- Descending canonical index order for bulk mutations (Phase 20 D-03/09)

Token deduplication and metadata preservation strategy:
- Avoid duplicate tokens in a single task (Phase 34 D-08 / TAG-03 requirement)
- Preserve non-target tokens, completion markers, and metadata

  <files>crates/todotxt-tui/src/app.rs</files>
  <action>
Implement `handle_quick_setter_key` to process user input while the quick setter is active:

1. For character keys (a-z, A-Z, 0-9, hyphen, slash, etc.):
   - Append to `self.autocomplete.prefix`
   - Re-rank candidates: call `rank_matches(prefix, original_candidates)` to update `self.autocomplete.items`
   - Reset `self.autocomplete.selected` to 0 (top of new list)
   - Set `self.autocomplete.focused = false` (user is typing, not navigating)

2. For Up/Down arrow keys:
   - Navigate through `self.autocomplete.items` (same as existing autocomplete behavior)
   - Set `self.autocomplete.focused = true` when Down moves into the list

3. For Backspace:
   - Remove last character from `self.autocomplete.prefix` if non-empty
   - Re-rank and reset selection

4. For Tab / Enter:
   - Accept the currently-selected candidate
   - Call `apply_token_to_tasks(trigger, token, targets)` to mutate the active or selected tasks
   - See Task 4 for apply logic
   - Exit QuickSetter mode

5. For Esc:
   - Cancel without mutation
   - Exit QuickSetter mode back to Normal mode

6. For any other key:
   - Cancel and pass through to Normal mode handling (so other hotkeys work)

Per D-06, keyboard behavior is consistent across @/+ pickers and existing autocomplete.

<task type="auto">
  <name>Task 4: Implement idempotent token application and multi-select support</name>
  <files>crates/todotxt-tui/src/app.rs</files>
  <action>
Implement `apply_token_to_tasks(trigger: char, token: &str, targets: Vec<usize>) -> Result<()>`:

1. For each target task in descending canonical index order (Phase 20 D-09 pattern):
   - Extract the task line from `self.task_list.tasks[idx]`
   - Parse the task to check if it already contains the same token
   - If token exists (case-insensitive, with same trigger), skip (idempotent per D-08)
   - If token does not exist, append it to the task line
   - Apply `normalize_line` to ensure token order and format consistency
   - Preserve all non-target metadata (completion markers, dates, priorities, etc.)
   - Update the task in the task list

2. Determine targets based on selection:
   - If `!selected_tasks.is_empty()`, apply to all selected tasks (per D-01)
   - Otherwise, apply only to the active cursor task

3. After mutation:
   - Clear `selected_tasks` and reset `disjoint_select` (per Phase 20 D-04 pattern for consistency)
   - Return to Normal mode
   - Provide brief feedback: "Added @{token}" or "Added +{token}" in status bar

4. Ensure duplicate prevention:
   - Check for existing token using case-insensitive matching
   - Per D-08, idempotent application means no duplicate tokens added to a single task
   - Per TAG-03, preserve all non-target metadata

5. Handle edge cases:
   - Empty token: cancel without mutation
   - Invalid task index: log error, skip
   - Group header in selection: skip (per Phase 20 D-05 enforcement)

Token format validation:
- Token must be alphanumeric + allowed special chars (hyphen, slash per CONTEXT.md examples `@email/waiting`)
- Store token WITHOUT the trigger char (items in autocomplete are already trigger-free)
- When applying, prepend trigger: `@` + token = `@context`, `+` + token = `+project`

Per D-07, quick setters are add-only by default — they do not remove existing tokens (unless token already exists, in which case it is already present, so no-op).
  </action>

  </verify>
  <done>Tokens apply idempotently to single and multiple tasks, duplicates are not added, non-target metadata preserved, bulk apply uses descending index order, selection cleared after mutation</done>
