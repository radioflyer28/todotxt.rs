## Objective

Implement date autocomplete for partial `due:` and `t:` tokens and add the `s` due-date picker with month-aware day suggestions and weekday labels.

**Purpose:** Enable fast date entry during task creation/editing and provide a dedicated due-date setter that reuses the same date suggestion engine.

**Output:** Date autocomplete (DATE-01/02/03) + `s` due-date picker (CAP-03/DATE-04) with atomically committed task mutation.

Add handler to `handle_normal_key` for the `s` key:

1. Check if `active_pane` has a focused task row (not a group header).

2. If focused row is a task, initialize a `DatePickerState` with the current month from the system clock (chrono::Local::now()).

3. Set `self.date_picker = Some(DatePickerState::new("YYYY-MM"))` and transition to a new `AppMode::DatePicker`.

4. Render the date picker using the same popup overlay logic as autocomplete:
   - Header: "Set due date (arrows to navigate, Tab/Enter to select, Esc to cancel)"
   - Month/year display at the top
   - List of day suggestions (01 Mon, 02 Tue, etc.) with highlighting on the selected day
   - When user selects a day, construct the full `due:YYYY-MM-DD` token

5. When user presses Enter on a selected day:
   - Extract the day number from the selected suggestion
   - Build the full date string "YYYY-MM-DD"
   - Mutate the active task: remove existing `due:` token (if any) and append the new `due:YYYY-MM-DD` token
   - Apply via normalize_line to ensure token order and format
   - Commit the mutation and return to Normal mode
   - Selection and active row remain unchanged

6. When user presses Esc or BackEsc, cancel without mutation and return to Normal mode.

7. When user presses Up/Down in DatePicker mode, navigate the suggestions list (same behavior as existing autocomplete navigation).

The date picker reuses the same `render_autocomplete_popup` or a similar popup-rendering function per D-13.

Per D-01 and D-03, the `s` key is a lightweight inline picker, not a full-screen modal.
