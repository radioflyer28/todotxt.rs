## Threat Model

<threat_model>

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor content → save_and_exit | User-typed task line (full replacement); passed to `normalize_line` which is already hardened |
| CLI arg --normalize text → commands::append::run | `text` is user-supplied CLI arg; passed to `normalize_append` which is already hardened |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-06 | Tampering | save_and_exit Editing arm | mitigate | Use `normalize_line(&text)` not `normalize_append(original, &text)` — prevents body doubling when full task line is replaced (see 21-RESEARCH.md body-doubling trap) |
| T-21-07 | Tampering | AppMode::Adding arm | accept | Adding arm is NOT changed — always uses `Task::parse(&text)`; normalize_edit intentionally excluded from new-task creation (RESEARCH.md) |
| T-21-08 | Denial of Service | CLI append normalize flag | accept | `normalize_append` is already hardened; no new attack surface from CLI flag |

</threat_model>

```rust
fn save_and_exit(&mut self) -> color_eyre::Result<()> {
    let text = self.editor.lines().first().cloned().unwrap_or_default();
    let mode = self.mode; // Copy
    match mode {
        AppMode::Adding => {
            // T-21-07: Adding always uses Task::parse — normalize_edit does not apply here.
            // User is creating a new task from scratch; there is no "original" to merge into.
            let task = Task::parse(&text);
            self.task_list
                .add(task)
                ...  // (keep existing code unchanged)
        }
        AppMode::Editing { original_idx } => {
            // D-05/D-06: normalize_edit = true (default) applies normalize_line.
            // normalize_line lifts inline priority tokens from body to canonical position
            // and rebuilds via rebuild_raw. Does NOT merge onto original task — T-21-06
            // (avoid body-doubling: user has typed the entire replacement line).
            let task = if self.config.normalize_edit {
                todotxt_core::normalize_line(&text)
            } else {
                Task::parse(&text)
            };
            self.task_list
                .update(original_idx, task)
                ...  // (keep existing code unchanged)
        }
        _ => {}
    }
    ...
}
```

**Scope of change:** Only the position of `let task = ...` and the Editing arm's task
construction change. Everything else in `save_and_exit` (the display_rows rebuild,
`self.selected` update, `self.editor = TextArea::default()`, `self.mode = AppMode::Normal`,
`apply_pending_reload()`) stays exactly as is.

**Import:** Add `normalize_line` to the existing `use todotxt_core::` import at the top
of `app.rs`. If it already reads `use todotxt_core::{normalize_append, Task, ...}` (from
Plan 21-02), add `normalize_line` to the same import list.
</action>

Replace with:
```rust
    /// Append text to the end of a task
    #[command(alias = "app")]
    Append {
        /// 1-based task ID
        id: usize,
        /// Text to append (leading space added automatically)
        text: String,
        /// Parse and normalize todo.txt tokens in TEXT (priority, +project, @context,
        /// due:, t:) into canonical field positions instead of raw string concat.
        /// Without this flag, existing behavior (raw append) is unchanged.
        #[arg(long)]
        normalize: bool,
    },
```

**Why `bool` not `Option<bool>`:** `#[arg(long)]` on `bool` makes it a presence flag
(`--normalize` sets it to `true`, absence leaves it `false`). This is the standard
clap pattern for opt-in flags. D-10 says: CLI normalization must be explicit; no config
auto-read.
